# Qoder 插件容量设置与界面改版设计（已批准并实施）

用户已明确批准本设计。实现与验收见 `docs/provider-settings-validation.zh-CN.md`；下文保留设计阶段的现状记录，不作为当前代码状态。

## 目标与现状

目标：提供可选上下文（包括 500K、1M）和最大输出 token 设置，重新组织前端呈现，并修复本次涉及的数据与状态问题。

当前工作树基于 `56cdc08`，检查前无未提交改动。2026-11-03 执行 `npm test`：60 项通过。此结果仅证明当前自动化基线，不代表新功能或 Desktop 已验收。

当前代码事实：

- `src/client/card.tsx` 仅提供 PAT 与额度开关，容量没有专用编辑界面。
- `src/index.ts` 已有 `maxTokens`（默认 32768）和 `defaultContextWindow`（默认 1000000），根配置及 `providers.qoder-cn` 均可配置，后者优先。
- `src/adapter.ts::contextWindowOf` 将 `context_config` 多档位压成一个值，优先默认档位。测试 fixture 中已有 200K 默认与 1M 可选档位。
- `resolveModel` 的上下文优先级为目录 → 内置值 → 回退值；输出默认值优先目录 → 连接值。修改连接值未必改变 DSH 实际采用的输出预算。
- 请求同时写入 `parameters.max_tokens`、`model_config.max_output_tokens`，尚无明确的上下文档位选择映射。
- `src/client/settings.ts` 的 describe 返回 `ok:false` 时没有设置 failed，用户可能看到关闭状态而不知道读取失败。
- `src/client/quota.ts` 刷新失败会移除上次 report；界面无法同时展示旧数据和本次失败。

## 方案比较

1. 仅在现有卡片增加两个输入框：改动少，但不能充分解决模型目录优先级、上下文档位和信息呈现问题。
2. **推荐：保留 DSH 原生入口，重做 Qoder 设置卡片和额度面板，补齐容量解析及请求链路。** 不增加运行时依赖，保留当前账户与传输结构。
3. 独立提供商管理中心：自由度高，但重复 DSH 的路由、模型选择与导航功能，扩大维护成本。

## 架构与数据流

界面输入 → Host settings（llm-qoder）→ 配置解析 → 模型能力解析 → DSH 上下文预算 / Qoder 请求输出限制。

PAT 输入 → Host credentials。PAT 不进入 settings、不回显、不进入诊断或截图。

Host quota remote → 客户端共用状态 → 设置概览 / 侧栏卡片 / 额度面板。共用刷新结果，关闭侧栏时继续保持当前无后台轮询行为；用户主动打开面板时允许刷新。

学习重点：上下文窗口决定 DSH 保留多少历史、何时压缩；最大输出决定单次回答预算。两者必须分别设置。填写 1M 本身不能扩大模型服务端能力。

## 容量行为

- 上下文提供「自动（模型默认）」「128K」「200K」「256K」「500K」「1M」与自定义正整数。K=1000，M=1000000。界面显示精确 token 数。
- 输出提供「自动（当前兼容行为）」「8K=8192」「16K=16384」「32K=32768」「64K=65536」「128K=131072」与自定义正整数；输出预设直接标注精确值，避免与上下文 K 单位混淆。
- 使用单独的显式容量覆盖字段，保留现有 `defaultContextWindow` 与 `maxTokens` 的回退语义，避免已有安装被静默改变。支持提供商默认与按模型覆盖；模型覆盖不复制整个静态 models 数组，不中断动态目录发现。
- 配置路径必须尊重 `providers.qoder-cn` 的覆盖关系。客户端显示实际生效层级，修改同一层；只写用户编辑的字段，保留其他字段。
- 自动模式不改变当前解析结果。显式模型覆盖优先于显式提供商覆盖，随后使用现有目录 / 内置 / 回退逻辑。
- 保留目录返回的上下文档位及对应原始标识。选择服务端支持的档位时，需要将正确标识映射至请求；实现前从可获取的 Qoder 客户端源码或实际请求验证字段，不能猜测协议。
- 500K、1M 必须能被选择和保存。已知模型不支持的值显示明确能力提示，不把它标成已支持；若只能改变 DSH 的本地预算，必须标为「本地预算覆盖」，不得声称扩展服务端窗口。
- 输出在模型已知上限与有效上下文预算内取合法值；显式请求值可以覆盖默认值，但不能绕过已知硬上限。`resolveModel` 的默认输出与最终请求采用同一套解析规则，两处 wire 输出值必须一致。
- 校验拒绝 0、负数、小数、非有限值和不安全整数。上下文必须给输出保留空间；错误发生在保存或请求发送前，并显示可纠正的信息。
- 恢复自动仅删除新覆盖字段，保留旧配置。保存后重新读取 Host 状态，再显示成功；验证后续请求使用新设置，当前进行中的请求保持其启动时快照。

## 界面设计

### 设置卡片

- 顶部：Qoder CN 名称、凭据状态。区分「已配置」「未配置」「读取失败」；已配置不等于连接验证成功。
- 账户区：紧凑的密码框与保存按钮，已配置时提供更换入口。读取中与只读状态禁止误提交，保存失败保留输入供重试。
- 模型与容量区：提供商默认设置、可展开的按模型设置、自动/预设/自定义控件；并列展示上下文和最大输出；显示目录能力与有效值及来源。窄屏改为单列。
- 额度概览：简洁的已用/总额、账期、更新时间和手动刷新；更多详情进入已有额度面板。
- 集成区：保留侧栏开关。端点等已有高级配置不混入常用容量输入。

### 额度与侧栏

- 面板以账户/套餐摘要、额度池、账期、刷新状态组织，保持个人与组织池的语义，缺失值显示未知，不按 0 处理。
- 侧栏保留折叠态圆环与展开态紧凑摘要，不增加全局导航结构。
- 失败时保留最后一次成功 report，明确标「上次数据」与时间，同时展示失败及重试；从未成功时使用空态。
- 沿用 DSH 主题变量，样式限制在插件命名空间内；检查浅色、深色、窄屏、折叠侧栏和键盘焦点。
- 中文和英文同步更新，状态通过文字及 aria 状态表达，不只依赖颜色。

## 本次顺带优化的边界

- 修复设置读取失败被当作正常关闭，以及容量写入的 revision 冲突处理：冲突后重新读取并重试本次字段操作一次。
- 容量和额度刷新避免旧响应覆盖新状态；重复点击时禁用进行中的操作。
- 保持已实现的隐藏侧栏不轮询、共享刷新、资源释放和流式取消行为。
- 不引入多账户轮转、收费估算、新代理层或新的前端框架；这些不属于当前需求。

## 补充协议核查（2026-11-03）

- [Qoder 官方 SDK 示例](https://github.com/QoderAI/qoder-agent-sdk-samples/blob/main/python/model-selection/main.py)的 `context_windows` 同时读取 `availableContextWindows` 和 `context_config.*.token_count`；`default_context_window` 独立解析默认档位。说明保留全部档位与默认值是正确的数据模型，不能把默认值当作最大值。
- 同一示例的 `policy_result` 把所选窗口作为 `parameters.contextWindow` 数值传给 SDK 的模型策略。这证明官方 SDK 支持显式选择窗口，但不证明本插件直连 gateway 应使用同名 JSON 字段。该示例随后由 SDK/CLI 处理请求，属于不同的协议层。
- [Qoder CN SDK 类型参考](https://docs.qoder.cn/cli/sdk/references-typescript)的检索结果也将 `context_config` 定义为层级标签到 `token_count` / `is_default` 的映射；本次完整页面访问超时，以成功获取的官方示例源码作为主要证据。
- 已找到本机 `qodercn.cmd` 入口，可在实现阶段进一步定位 CLI 对 SDK 参数到 gateway 字段的转换。此次未启动 CLI、未读取凭据、未发送付费生成请求。
